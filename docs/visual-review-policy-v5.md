# 主体识别与结构质量复核

## 2026-09-26 误通过根因

旧规则只要求主体可辨识，明确豁免车架拓扑和脚踏接触；只有首轮否定主体才追加观察。首轮全部为 true 时直接通过，动作、场景和循环等建议项也不会否决。因此“看得出是鸟和自行车，但结构已经损坏”的画面可能被放行。仅强化一次提示词仍在历史截图回放中出现误通过。

## 当前判定流程

1. 使用原始 12–16 帧观察主体。普通卡通比例、配色、简化辐条和链条不作为失败原因。
2. 首轮否定主体时进行一次同证据确认。两次相同否定才构成主体失败；分歧保留未知，不选择其中的通过结论。
3. 首轮无否定，或两次主体观察有分歧时，发起单独的结构质量请求，不传入前轮结论。检查鸟体完整性、两轮与车架/承托/转向结构的连接、座位承托以及腿脚和曲柄的关系。
4. 质量轮明确失败会否决通过；每个核心明确结论必须引用至少两个不同帧编号。遮挡或小尺寸看不清时为未知，不能当作缺失。缺证据、格式错误、超时或请求次数耗尽均保留待复核。
5. 质量轮通过也不能抹去主体识别的分歧；只有主体与质量均满足条件才能通过。自行车未确认时不能同时宣称骑乘正常。

两轮是独立请求与不同观察标准，不代表统计独立，也不会自动换模型。后台选择的同模型自评或外部审核提供商同时用于这些请求；没有偷偷回退。视觉模型仍可能产生相关误判。

## 稳定性、成本和证据

- 保留原有审核总截止时间，默认 240 秒、单请求至多 120 秒。重复观察、网络重试和格式回退共享预算，不自动无限追加。
- 默认请求上限为 retry_count + 1。首轮无主体否定时至少允许两次观察，即使 transient retry_count 为 0，也留一个质量观察名额；不增加首轮网络重试次数。
- 成功路径通常由一次审核变为两次；主体分歧时最多使用默认的三次请求。模型额度与延迟会增加。预算不足时保留证据，返回待复核。
- 两轮复用相同的不可变截图。保存 purpose、帧引用、原回复哈希、用量、quality_gate 及 quality_failures。
- 前端分别显示结构质量未通过、待复核和执行异常，不将质量轮缺失解释为画面通过。
- 动作、场景、校验码和循环仍为建议项；本次修复不是完整动画物理或美学评分。

## 历史记录

早期标准的通过结论没有当前质量轮证据，升级后归为待复核，并保留 previous_review、SVG、截图、原时间和糖果结果。不伪造新模型判断。v4 已有两次一致的主体失败证据继续保留为失败。迁移幂等。

replay_review.py 校验 SVG 和各帧哈希，仅输出单独重审报告，不修改历史记录。历史真值不能通过把样本硬编码成失败来构造。

## 回归与后续校准

自动化覆盖质量否决、分歧后复核、质量通过不能抹去分歧、单帧证据不足、请求/格式故障、零重试名额、次数耗尽、检查项依赖及各旧版本迁移。

后续应建立人工标注的保留集，覆盖正常简笔画、明显断车架、悬空骑乘、遮挡、静态脚踏、背景假运动和复杂循环，重复评估误通过与误拒绝。当前历史回放只是案例验证，不是整体准确率或模型降智证明。
