## 已确认的根因和证据边界

1. **访客整轮时间预算固定为 300 秒。** `Monitor.prepare_guest()` 用 `validate_settings(values, DEFAULTS)` 构造配置，允许字段里没有 timeout_seconds。`execute_guest()` 再用这个 300 秒设置硬截止时间。修改后台“生成超时”不影响访客。5 轮集中在 299.37–300.03 秒结束，说明本地硬预算确实是这些失败的共同限制。
2. **重试不增加整轮预算。** `request_with_retries()` 中的首次请求与重试受同一个 stage/task deadline 约束。慢请求消耗大部分预算后，下一次请求只能拿到余下的时间；勾选更多重试并不等于拥有更多等待时间。现有配置也没有给生成重试设置最低可用时间。
3. **另有两轮明确的上游 404。** 这两轮在 1–3 秒内结束，与 300 秒预算无关。请求代码根据协议拼接 `/responses` 或 `/chat/completions`，404 指向接口路由、模型路由或协议配置问题。历史记录未保存协议与完整地址，不能断言究竟是哪条路径错误，也不应携带密钥自动探测其他站点。
4. **诊断信息在访客落盘时丢失。** `perform_test()` 已产生 stage、error_code、attempts_log，但 `execute_guest.persist()` 的旧白名单只保留 attempts 总数等字段。整轮超预算的中文消息没有命中 `guest_error()` 的“超时”匹配时，会显示为泛化的“连接或生成失败”。旧日志仅包含阶段、代码、次数，没有任务 ID，无法逐条还原。
5. **旧记录只有 1 小时/最多 100 条的公开保留期。** `prune_guests()` 直接删除原数据，没有管理员独立历史。故障发生后稍晚再看就失去证据。

上游首包慢、生成慢、流式心跳或最终事件异常均可能进一步消耗预算；当前证据不足以区分每次的具体上游原因。旧实现对 Responses 使用流式请求、对 Chat 使用非流式请求，流式读取另有 90 秒空闲上限。日志确实出现 http_524、timeout、deadline、empty_response 等，但不能在没有任务关联信息时将所有日志硬配到某一条访客记录。xhigh 与更长推理时间相容，是预算压力的合理解释，不能仅凭这些记录认定模型本身退化。

入口 Nginx 虽然也配置了 300 秒 proxy_read_timeout，但访客提交接口返回 202，之后轮询读取后台任务；目前失败记录来自应用内部截止时间，不支持将入口代理作为这批失败的主因。

## 解决方案与验收顺序

本次已实现可观测性和后台记录，不更改检测时间预算、推理强度、模型、答案标准或现有收费请求行为。

1. **先补证据（本次落地）。** 后台新增“访客检测记录”，支持整轮状态和检测项目筛选、每页 20 条、查看分项耗时、错误码、请求次数及重试明细。新任务记录实际协议、时间预算、输出上限。结构化失败日志增加 task_id 与检测项目。回填尚存旧记录，缺失字段显示“历史未记录”。
2. **再将访客预算独立配置。** 建议新增 guest_timeout_seconds、guest_max_output_tokens 等明确配置，避免误以为后台设置适用于访客。可从普通检测 300 秒、高强度检测 600 秒的有界方案做小规模验证，界面在提交前展示预计预算。继续使用异步排队和硬截止时间，不通过扩大 Nginx 超时掩盖应用问题。
3. **按可用预算与进度决定重试。** 429/可恢复 5xx/连接失败保留有限退避，401/403/404 不盲目重试；慢生成第一次已占用大部分预算时，避免再发只能执行几秒的重复计费请求。优先为生成重试设置明确的最低可用预算，同时保留整轮上限；不能简单把每次尝试缩到很短而加重慢模型失败。
4. **精确呈现失败类型。** 前端区分任务总预算耗尽、流式空闲超时、上游 524、接口 404、输出未完成和答案不合格，保留糖果已通过等分项结果。以稳定错误码映射文案，避免用中文字符串猜错误类型。
5. **用同一条访客接口做受控复测。** 由持有密钥的用户在页面重新提交，分别比较 Responses/Chat 的实际可用协议，以及 medium/high/xhigh 的成功率与耗时分布。至少记录预算命中率、首包/首个有效内容耗时、完整生成耗时、重试是否有效和实际用量。只有这些证据齐备后才调整长期默认值。

## 记录功能的数据边界

- 新表 guest_history 独立保存脱敏元数据，保留 30 天、最近 10,000 条，活动任务不因清理被删除；清理随任务结束及调度器周期执行。
- 公共结果表仍为 1 小时、最多 100 条终态结果；公开查询不会暴露新增的后台诊断信息。
- 历史不保存 API Key、完整接口地址、请求头、原始错误响应、原始答案或 SVG。只保留脱敏接口名、提交模型、协议、强度、状态、检查结论、时间、用量和固定诊断字段。
- GET `/api/admin/guest-records?page=1&status=all&test=all` 使用现有管理员会话鉴权；未登录 401、无效筛选/分页 400。退出登录清空页面记录。
- 旧版已删除的数据不能凭空恢复；旧记录缺失的协议和错误码也不会根据猜测补造。
